# AI handover and adoption checklist

**Tool / agent / workflow:** · **Owner after handover:** · **Handover date:**

Use this when an AI tool, agent, skill or automation moves from "the person who built it" to "the team that relies on it". Tick each item, or write why it doesn't apply.

## 1. It's documented
- [ ] One-paragraph description of what it does and what it doesn't do
- [ ] Where it lives (link to the agent, skill file, workflow or notebook)
- [ ] The exact prompt or instructions, saved somewhere other than one person's chat history
- [ ] An example of good output
- [ ] Known limits ("where it falls short")

## 2. It's owned
- [ ] A named owner who will fix it when it breaks
- [ ] A named backup
- [ ] It doesn't run under a personal account that will leave with the builder
- [ ] Owner has edit access to everything it depends on

## 3. It's safe
- [ ] What data it reads is listed
- [ ] Whether it acts on anyone's behalf (sends, files, approves) is stated
- [ ] A person checks the output before it's relied on, and who that is
- [ ] Consent process if it records people
- [ ] IT or governance sign-off, if your organisation requires it

## 4. It's affordable
- [ ] Licence type needed by each user (Copilot Chat / Microsoft 365 Copilot / Copilot Studio)
- [ ] Usage-based costs estimated (runs per month × cost per run)
- [ ] Who gets the bill

## 5. People can use it
- [ ] Users have been shown it, not just sent a link
- [ ] A one-page how-to or a two-minute video exists
- [ ] Where to ask for help is clear
- [ ] Feedback route (channel, form or Friday check-in)

## 6. It stays working
- [ ] "Last verified" date recorded
- [ ] Re-check scheduled (monthly for anything in preview, quarterly otherwise)
- [ ] What to do if Microsoft changes or removes the feature
